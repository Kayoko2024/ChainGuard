# 威胁模型与信任边界

状态：SPECIFIED；运行时隔离与全部业务防线 TODO。

保护资产：用户真实任务授权、受限文档、邮件/删除执行权、批准签名、工具签名、密钥、策略版本、幂等记录、链下证据和多方共同历史。

## 参与方和凭据

| 主体 | 持有 / 可以做 | 禁止 / 信任边界 |
|---|---|---|
| 用户 / REQUESTER | 在独立签名端逐动作确认 ActionIntent；创建链下 TaskGrant | 用户身份与链地址必须登记绑定；Agent/网关不能代持用户私钥并自动批准 |
| Agent / AGENT | 读取允许的输入；向网关提出结构化意图 | 外部材料不可信；无工具凭据、请求者/批准者/工具签名密钥或治理密钥 |
| 网关 | 参数校验、策略、收集签名；独立交易提交账户只负责 Gas | 提交交易不等于批准；不信任 Agent 传入的 risk、组织和权限 |
| OrgA 业务 / OrgB 安全 | 使用独立身份和密钥批准同一意图 | 同一账户不可重复计数；同组织多账户不能满足跨组织约束 |
| HUMAN_APPROVER | R3 显式人工复核的独立第三个签名账户 | 系统不能仅凭签名证明现实人已阅读；界面、部署与操作流程是前提 |
| OrgC 审计 | 只读重建事件与证据；受控对账服务另有 RECONCILER 密钥 | AUDITOR 不自动获得批准、治理、执行或证据明文访问权 |
| 工具服务 | 唯一持有敏感工具真实凭据和独立 TOOL_SIGNER；自主核验链与任务授权 | 工具本体可信；被攻陷的工具可能对现实副作用说谎，单靠区块链无法纠正 |
| 验证节点 / 治理 | 共同维护 QBFT；治理变更要求不同组织门槛 | 同机四容器不能证明真实跨机构独立性；网关不得持有全体管理权限 |

## 攻击矩阵

| ID | 攻击者能力 / 入口 | 目标 | 要求的强制控制 | 后续可观测验收 |
|---|---|---|---|---|
| T01 | 修改邮件/网页/文档正文，间接提示注入 | 外发未授权资料 | TaskGrant + 确定性策略 + 工具重新核验 | 记录尝试、两侧拒绝及实际邮箱新增条数 |
| T02 | Agent 进程失陷或构造隐藏工具调用 | 绕过网关执行 | Agent 无凭据；工具网络只接受网关；工具仍查链 | 直连被拒、工具副作用数 0 |
| T03 | 网关改写收件人、正文或盐 | 替换获批参数 | 双端规范化、域分离盐承诺、准确意图签名、工具业务范围校验 | 一字节变化导致承诺不符且无副作用 |
| T04 | 获取一个批准密钥或多个同组织账户 | 凑出跨组织批准 | 从签名恢复地址；查当前角色和组织；去重 | 缺签、同组织、重复、已撤销账户均拒绝 |
| T05 | 复制历史许可、并发调用、跨链投递 | 重放执行 | EIP-712 域；永久 actionId/nonce 消费；工具数据库唯一键 | 同 actionId 并发和重启后最多一个真实副作用 |
| T06 | 在已预约后撤销角色/策略 | 使用旧许可 | 工具重查当前纪元、全部签名人的撤销状态和暂停状态 | 在二次核验前已撤销的未执行动作拒绝 |
| T07 | 单机构数据库管理员删改日志/审批状态 | 伪造批准或抹除历史 | 其他组织签名、独立节点历史、加密证据的承诺和签名 | 篡改冲突可定位；缺原文报告 PARTIAL |
| T08 | 阻断/重复网络、丢回执、RPC 超时 | 离线放行或二次发送 | fail closed；真实确认；持久回执队列；UNKNOWN 对账 | RPC 广播不明不执行；回执晚到只补锚定 |
| T09 | 路径穿越、符号链接或 Unicode 混淆 | 访问真实主机文件 | API 只用不透明 doc_id；可信目录映射；打开后校验真实沙箱边界 | 主机不挂载真实敏感目录；越界与链接用例失败 |
| T10 | 提交恶意审计证明、伪造工具签名 | 显示虚假成功 | 绑定 actionId/paramsCommit/工具ID与工具签名角色；重算摘要；查真实事件 | 假证明、错工具签名、冲突回执拒绝 |
| T11 | 普通管理账户修改角色或解除暂停 | 自授权限 | 不同组织治理批准；治理 nonce、时效、事件；紧急暂停不能单方解除 | TODO：治理协议与实施阶段的独立负例 |

## 明确假设和限制

- 工具端使用自己受控的、配置固定 chainId/合约地址/代码身份的链客户端；调用者提交的 tx_hash、block_number 或所谓证明只用于定位，不能当作可信确认。受控 RPC 及其节点不被工具调用者替换。恶意 RPC/大范围验证者串通超出当前可信链假设。
- QBFT 四验证者至多一名拜占庭节点的容错前提、节点间连通和独立管理须明确；必须实际测试节点停止后的行为，不能从理论直接写实测结论。
- 工具二次核验使用最新可确认状态。核验之后与副作用之间仍有撤销竞态；报告确切观测区块和执行时间，不承诺链外原子撤销。
- 策略只能保证明确授权边界。授权范围内的语义滥用、错误人审、错误资源标签无法由哈希自动发现。
- 请求者签名只证明该密钥同意精确意图，不能独自证明完整任务文本语义；TaskGrant、组织身份、资源标签由可信服务保存并在网关和工具检查，合约仅核验可编码的身份/策略字段。
- 本地邮箱若用同一数据库事务写邮箱记录和幂等记录，可以设计严格单次提交。真实不可回滚第三方 API 若无原生幂等键，不能宣称 exactly-once。删除涉及文件系统与数据库的崩溃窗口，需持久操作日志和 UNKNOWN，不能凭“文件不存在”推断谁执行了删除。
- 所有攻击只作用于本地测试邮箱和可丢弃容器文件；禁止向真实外部邮箱投递，禁止删除真实文件。原始数据和随机盐不上链，工具私钥/节点私钥/API Key 不入库。
- 阶段 0 测试只证明密码学和接口一致性；网络隔离、业务授权、合约防重放、真实副作用与四节点容错仍全部 TODO。
