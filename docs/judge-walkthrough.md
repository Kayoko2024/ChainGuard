# ChainGuard 评委独立操作与核验流程

适用范围：阶段10、真实 DeepSeek、LOW 自定义查询会话、R2 `mail.send`、四节点 Besu、本地测试邮箱。无需阅读源码。未完成的研究实验仍见 [项目缺陷审查](../results/review/20261027-project-audit-01/PROJECT_REVIEW.md) 和进度记录。

## 打开哪里，以及验证什么

| 入口 | 你能操作或检查的内容 |
|---|---|
| [业务操作台](http://127.0.0.1:8090/) | 现场输入新任务、真实模型提议、两个组织人审、请求者确认执行、查看原邮箱 |
| [动态只读审计台](http://127.0.0.1:8091/) | 自动出现新动作、实时检查审批/交易/工具签名，不提供执行权限 |
| `scripts/verify_demo_task.py` | 按你自己的业务任务 ID，从原记录、只读原工具卷和四节点 RPC 独立核验，生成可读报告和原始 receipt |

业务台默认进入对话：首次发送创建会话，后续发送在同一会话延续上下文，刷新后仍能看到所有轮次；点击“新建会话”才另开对话。旧版独立任务保留原样。默认工具与外部接入统一在“工具与设置”；会话创建后工具、资源和附件授权固定，改变范围需新建会话。选择任务后点“审批与证据”，审批身份会自动打开审阅面板；手机用“历史任务”切换。

8080 是旧阶段9历史快照，本次不要用它寻找新任务。业务台显示 `FINALIZED_OK` 仍须实时核验；网页颜色、截图、HTTP 200 都不是执行证明。

项目演示的核心用途是：**模型只能提出动作；明确任务授权、不同组织的批准和工具端核验共同决定是否实际发送，并将结果留作可查证记录。** 当前不证明模型语义判断永远正确，也不证明 C 组的模型防御效果优于 B 组。

## 准备（只需一次）

1. 在本机打开 `D:\CCF\.local\phase10\20261026T123255815352Z\access.local.txt`，获取 requester、biz、security 三个测试身份的密码。不要发到聊天、报告或投影屏幕。
2. 准备三个互相独立的浏览器配置/会话，分别登录 requester（请求者 OrgA）、biz（业务审批 OrgA）、security（安全审批 OrgB）。普通窗口和标签通常共享 Cookie；两个隐私窗口也可能共享同一隐私会话。也可在同一页退出后换身份，但会占用审批时间。
3. 新邮件任务授权有效 **24小时**，审批与执行的实际截止时间显示在动作卡片上，且不能晚于任务截止。两个组织批准后仍须请求者确认预约。旧120秒动作保持原期限；过期须新建一轮明确请求，不能迁移旧审批。
4. 打开8091，确认联盟链为 ONLINE、显示四节点共同高度。过几秒再次刷新应看到高度变化。若服务离线，用项目 README 的恢复命令；不要删除卷、重置链或重建合约。

## 第一幕：你现场新建并完成一封邮件

推荐先演示连续对话：选择 meeting-notes 的读取权限及 mail.send、Alice 本地收件人，发送“读取 meeting-notes，总结负责人和下一步，先不要发邮件”。收到真实摘要后直接在底部输入“把你刚才的完整摘要发给 Alice，主题为我的新标记”，不要点击新建。应保留同一会话 ID、显示两轮消息，邮件动作挂起。按下表完成双审批和请求者预约；只有原链和工具核验通过，Agent 才会自动继续回答。刷新仍应保留两轮和回执。

默认 LOW 读取使用一次 OrgA 会话签名，后续同范围查询共用额度；不会每次要求 OrgB。点击“结束会话并存证”（或等5分钟／50条），LOW 日志的会话根提交真实链；到8091选 `conversation-…` 记录核验 `BATCH_VERIFIED`。邮件不进入 LOW 根，仍逐动作 reserve/finalize。结束会话不将未知调用标成成功；在途 LOW 无结果时最终根须等待。旧任务级演示的 `batch-…` 记录继续可查。

也可先演示 LOW 免审：requester 在“工具与设置 → 接入与管理”注册查询工具，自行修改联系人或库存示例，不填写风险。security 点击该版本，核对资料／Schema 后**选择 LOW 并启用**，查看真实审核交易与区块。requester 选本版本和记录键准备任务，设置会话期限／最大次数，输入新问题并运行真实 Agent；应直接看到查询结果，无逐次审批。打开任务的“审批与证据”，查看 OrgA 会话和持久调用，点击“立即提交待存证批次”（也可等5分钟）。在8091选新增 `batch-…` 行并实时核验，应为 `BATCH_VERIFIED`，有区块、交易、根和 Merkle 路径。原始调用可用 README 的独立核验命令复核，截图不替代链证据。

把同一工具由 security 重新审核为 HIGH 后创建新任务，应停在 `AWAITING_TOOL_APPROVAL`；分别由 biz 和 security 核对精确参数／摘要并批准，再由 requester 确认。只批准一个组织不能执行。会话过期／超额也走这条逐次审批路径，UNKNOWN 不自动重发。HIGH 自定义查询没有获得任意写权限；邮件仍按下文原 R2 流程执行。LOW/HIGH 与原 R0–R3 是两个不同标签。

真实工具演示可选“接入方式 → 应用模板 · GitHub 仓库与 Issue”，展开“接入真实 GitHub 只读工具”填入 VS Code 验收用例（`microsoft/vscode` 和 `microsoft/vscode#1`；其他仓库当前被链策略拒绝），提交→security审核→requester选一个资源并准备任务→创建真实Agent任务。例如“查询这个Issue的标题、状态和主要内容，给出来源”。展开实际调用中的“GitHub实时来源”，核对HTTP200、请求ID、查询时间与响应摘要，再打开对应GitHub页面独立查看。GitHub是动态数据，当前页面可能与保存时点不同；只读复核命令读取保存的原始HTTPS响应，不用重新查询值覆盖历史证据。只授权仓库不会授权其所有Issue，未授权调用被工具端拒绝；只读不走R2链预约，审计为READ_ONLY_OBSERVATION。

自己的资料先选“接入方式 → 个人数据 · CSV / JSON”，展开“注册新的查询工具”，通过“导入 CSV / JSON”选择 UTF-8 文件，指定 CSV 数字/布尔列类型后“校验并预览导入”，再“将预览数据填入待审版本”。预览不会新增工具。已有最新版本可点“以此版本修改资料”，修改后提交 v2，查看父版本差异和事件历史，再由 security 审核；旧版本/旧任务不改变。启用后勾选“准备查询”记录键，点“用本版本准备 Agent 任务”，检查只读授权和任务内容后自行点击创建。数据是版本快照，不代表连接了实时业务系统。

也可直接点“填入联系人查询示例”或“填入库存查询示例”，完整名称/字段/资料和任务提示会填入。它们只准备输入，须自行提交、审核启用。新建只读任务时取消其他工具，仅勾选custom.contacts_lookup与CONTACT-001，查询姓名、部门和邮箱；或仅勾选custom.inventory_lookup与SKU-002，查询数量和预警线（合成资料为2与10），让真实Agent判断是否应补货。库存工具不修改数量、不下单，联系人查询不发信。想验证越权，可仅授权CONTACT-001却要求查询CONTACT-002，查看真实拒绝；读取审计仍不是链上认证。

再以requester登录，在任务工具中选该工具并勾选允许查询的记录键（如只选DEMO-1）。输入“查询DEMO-1的负责人和状态，不发送邮件”可看到真实模型查询和结果；若还勾选mail.send并要求发送查询摘要，则继续下面的原双组织精确意图审批和预约。修改资料须新版本，旧任务不会自动升级；security可停用版本，实际工具会拒绝后续查询。自定义查询的审计标签只表示R0本地日志观察，不能代替发送链上证据。

默认工具库现已可选。可以先点“示例：搜索并总结文档”，确认授权meeting-notes/project-brief，再创建任务，查看doc.list/search/read的真实调用与Agent总结；READ_COMPLETED无需审批或预约。也可点“示例：读取本地邮件”，单独勾选可读邮箱，查看mail.list/read；空邮箱会如实返回空列表。审计中的R0条目标明只读观察，不伪造链上交易。接着点“示例：读取后发送摘要”，模型先读纪要再提出mail.send，继续下面原双组织审批流程。所有示例都只是填写新任务输入，不替你创建任务或展示预置结果。

请自己取一个此前未用过的标记，例如 `JUDGE-当天时间-随机六位`，把下面的标记、正文换成自己的内容，粘贴到 requester 的“任务内容”：

仅勾选 Alice 作为允许的收件人，再点“发送任务”。**任务文本与授权勾选分开**，文本不能扩大工具权限。

如果模型没有提出动作，或显示 MODEL_ERROR/NO_ACTION，本次就是未完成，不能用固定 trace 补成模型成功。如果模型提出的正文不符合你的意图，不批准；参数承诺证明参数未被换掉，不代替你判断邮件内容是否正确。

## 一条命令核验你自己的任务

在 `D:\CCF` 打开 PowerShell，把任务 ID 替换为你刚复制的完整业务任务 ID。每次使用一个**尚不存在**的输出目录：

```powershell
& .\.venv\Scripts\python.exe scripts/verify_demo_task.py --task-id 0x替换为完整业务任务ID --out results/phase10/my-judge-send-01
```

退出码0且输出 PASS，表示默认期望的“链上完成且原邮箱恰好1封”通过。打开 `results/phase10/my-judge-send-01/verification.md` 看可读结论，`verification.json` 包含原始四节点交易 receipt、区块哈希、签名核验结果、MIME摘要。脚本不批准、不签名、不预约、不发邮件，也不调用模型，不需要浏览器登录令牌。

它检查的是：本地加密任务/实际模型 tool_call → 原网关动作 → 在无网络只读容器中重算原参数承诺 → 公开投影与原记录一致 → 原工具卷 MIME/结果/证据承诺/签名 → 四节点预约、当前状态、历史审批权限、finalize/reconcile、nonce 与交易区块成员 → 原冻结清单。报告不导出正文、盐或凭据。

这是可信本机操作员执行的核验，读取本地加密证据需要已有环境；不是不需要任何本机材料的第三方公共区块浏览器。JSON仍依赖所用核验软件、原私有证据可用性及本地链可信边界。

如果你还想完全绕开业务/审计服务检查交易，可从网页复制一笔真实 tx hash，直接查询四节点：

```powershell
$txHash = '0x替换为网页显示的真实交易哈希'
$rpcBody = @{ jsonrpc='2.0'; id=1; method='eth_getTransactionReceipt'; params=@($txHash) } | ConvertTo-Json -Compress
8545..8548 | ForEach-Object {
    $r = Invoke-RestMethod -Uri "http://127.0.0.1:$_" -Method Post -ContentType 'application/json' -Headers @{Host='localhost'} -Body $rpcBody
    [pscustomobject]@{ Port=$_; Transaction=$r.result.transactionHash; Status=$r.result.status; Block=$r.result.blockNumber; BlockHash=$r.result.blockHash }
}
```

应看到相同 transactionHash、blockHash 和 `status=0x1`。这一步只证明交易成功；邮件实际发送还必须看原 MIME 及签名回执，不能用普通转账或单独交易成功替代。

## 第二幕：缺审批、越权、重复执行都不能多发

先准备好三个身份会话，再**另建一条**仅授权 Alice 的新任务。在页面显示的24小时任务窗口内完成下列操作：

1. requester 审阅后，在0份或只有 biz 1份审批时点“发起链上预约并执行”。预期真实错误 `APPROVAL_MISSING`，审批不齐不能预约；详情无预约交易、邮件0封。不要把“任务创建成功”解释成执行成功。
2. 展开“隔离环境负例与 UNKNOWN 演示”，点“尝试任务范围外收件人”。预期 `UNAUTHORIZED_SCOPE`，返回的 gateway_actions_before/after 相等、mail_before/after 均为0；事件标注 MANUAL_NEGATIVE_CONTROL、agent_attempted_tool=false。
3. 若本条任务用于“未执行”核验，就保留它不执行，运行下面命令。若还要完成合法发送，必须在有效期内补齐另一组织审批并由请求者执行；不要等核验脚本结束才继续审批。

```powershell
& .\.venv\Scripts\python.exe scripts/verify_demo_task.py --task-id 0x替换为这条新任务的业务ID --expect unexecuted --require-negative-control --out results/phase10/my-judge-deny-01
```

此模式会核对越权拒绝及前后计数日志，重新读原邮箱确认0封，并逐个 RPC 检查四节点上该 Action ID 的预约状态均为 NONE。**PASS只表示此次未执行观察符合预期，不表示已完成发送。** 拒绝发生在链下时本来就无交易，不会生成假“拒绝receipt”。负例前后计数日志仍属于可信本机控制面的记录，不能单靠日志证明任意历史时刻的所有外部活动。

再回到第一幕已完成的任务，点“查询原记录 / 验证重复提交”，重新查看邮箱与交易。应保留原 Action ID、两笔原交易、同一 MIME摘要、邮件仍为1。可用新的 `--out` 再跑默认核验并与首次报告对照。这里验证的是原动作持久幂等；再次创建一个新任务属于新的授权动作，不是重放。

## 第三幕：UNKNOWN是真实不确定，不能再次发送

另建新任务，出现待批动作后，先点击“执行前启用真实回执丢响应”，再完成双组织审批并由 requester 执行。

1. 工具真实写入1封本地邮件，但测试适配器丢弃回执响应；网关显示 UNKNOWN。业务“查看真实沙箱邮件”仍应观察到1封；审计实时核验应为 PENDING_RECEIPT，有预约而没有完成交易。
2. 点“查询原执行状态（不会重发）”，邮件仍为1。不要重新创建动作来“补发”。
3. 若要留证，使用新结果目录执行：

```powershell
& .\.venv\Scripts\python.exe scripts/verify_demo_task.py --task-id 0x替换为UNKNOWN任务业务ID --expect unknown --out results/phase10/my-judge-unknown-01
```

此处 PASS 的含义是“确实观察到 UNKNOWN、预约和1封原邮件”，**不是成功完成**。

4. 点“解除丢响应并查询原回执”。系统仅取回原回执并锚定，等待 FINALIZED_OK；重新查原 MIME 和审计，再用默认核验输出到新目录。应是同一 Action ID、同一封邮件、同一预约和新完成证据，不发生第二次发送。

## 失败时怎样判断

| 现象 | 应采取的判断/处理 |
|---|---|
| APPROVAL_EXPIRED / 动作已过期 | 新建任务并重新审批；不延长或复用旧签名 |
| 两审批齐但 NO_RESERVATION | 尚未预约；切回 requester 审阅并执行。已过期则新建 |
| CHAIN_UNAVAILABLE / UNAVAILABLE | 当前核验未形成结论；保留报告，恢复链/历史查询后再查，不因此重发邮件 |
| PENDING_ANCHOR | 有本地回执、仍待真实链上确认，不能当 FINALIZED |
| MODEL_ERROR / NO_ACTION | 本次没有完整模型动作；检查服务配置，不能使用模拟响应替换 |
| AUDIT_PROJECTION_NOT_READY / PROJECTION_DIFFERS_FROM_GATEWAY | 动态投影尚未收敛或证据不一致，等网页更新后换新输出目录重查；持续失败须排查 |
| EXPECTED_ONE_ORIGINAL_ACTION | 任务未产生一个可核验的原动作；模型错误/无动作不冒充已发送 |
| 脚本 FAIL或非零退出 | 该期望未通过，以报告为准；UNKNOWN、未执行和完成必须使用各自期望 |
